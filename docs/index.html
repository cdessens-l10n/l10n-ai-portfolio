Flagship skill 1

Product UI review autopilot

An invocation-only agent skill plus batch CLI that reviews every EN→FR Product UI segment in scoped TMS jobs, scores confidence, uploads reviewed bilingual files, and auto-completes only when the job is a clean Pass.

Problem: Machine translation and TMS leverage look “done,” but linguistic risk lives in terminology residue, register, ICU plurals, key-path sense, and cross-segment drift. Rubber-stamping high TM matches ships errors.

Solution: Treat the agent as a final quality gate. Review every segment (including 100% and locked). Enforce glossary locks and typography. Complete only when score is 100 and automated gates pass; otherwise Hold with a pre-reviewed file and an explicit reason trail. 

flowchart TD
  start[Select scoped TMS jobs] --> preflight[Preflight and download bilingual baseline]
  preflight --> audit[Job-wide terminology audit]
  audit --> review[Per-segment review against glossary style TM and key path]
  review --> score[Score 0 to 100 plus hard gates]
  score -->|Pass 100 and gates OK| uploadPass[Upload confirm complete write TM]
  score -->|Hold| uploadHold[Upload reviewed file Needs human]
  uploadPass --> report[Batch report row]
  uploadHold --> report
  report --> next{More jobs?}
  next -->|Yes| preflight
  next -->|No| endNode[Batch complete]

Pass vs Hold

Decision Conditions What happens
Pass Score = 100 · every segment unchanged or typography-only · all hard gates pass Upload → confirm segments → job completed → TM write via TMS confirmation path
Hold Score < 100 · any substantive edit or human flag · any gate failure · upload/confirm failure Upload reviewed file only · marked for human finish · no auto-complete

Flagship skill 2

French terminology lookup

A governed research workflow: company termbase first, then official portals and competitor UIs, then an interactive decision to create or update glossary entries — including FR term notes that disambiguate sense for MT and LLMs.

Problem: Ad-hoc “how do we say X?” answers drift. Without evidence and notes, the next MT/LLM run reintroduces the wrong sense.

Solution: A skill that forces termbase-first lookup, optional external validation, comparison tables, and explicit human decisions before any glossary write — with note fields aimed at machine consumers, not just linguists. 

flowchart TD
  q[EN term question] --> tb[Search company termbase]
  tb -->|FR match exists| expand{Expand to portals and competitors?}
  expand -->|No| answer[Return glossary answer]
  expand -->|Yes| research[Portals plus competitor UI evidence]
  tb -->|Concept missing FR or no concept| research
  research --> compare[Comparison table and recommendation]
  compare --> decide[Human decision create update skip or bookmark]
  decide -->|Create or update| note[Draft FR term note for MT LLM disambiguation]
  note --> propose[Confirm entry proposal]
  propose --> write[Write termbase entry]
  decide -->|Skip| stop[Stop with recommendation only]

FAQ

Questions Localization leaders usually ask about the UI autopilot — plus terminology governance.

Does this replace human review?

No. It is a triage layer. Pass jobs leave the linguist’s plate; Hold jobs still need a human and typically carry ~90% of source words in a batch.

What makes a job Pass vs Hold?

Pass requires score = 100, only unchanged or typography-only segment dispositions, and every automated hard gate green. Any substantive edit, human flag, or gate failure → Hold.

Is the confidence score just TM leverage?

No. Score is computed on the final reviewed bilingual output after per-segment review — not on raw MT and not on TMS match %. Pass jobs are not filtered to “100% leverage only”; every segment is reviewed, including locked and perfect matches.

What kinds of edits does the agent make?

Purposeful quality fixes: glossary compliance, UI register/verb form, French typography (NBSP, apostrophes), ICU metadata cleanup, cross-segment consistency, and key-path sense. If a segment is already accurate and compliant, it stays unchanged — no cosmetic rewrites.

How was the reviewer role defined?

Final linguistic gate before Product UI ships — not a rubber stamp on TM scores. Review every segment; prefer key path as primary context; flag rather than guess when evidence is insufficient. CLI gates enforce the prose rules.

Is cross-segment consistency 100% guaranteed?

No — and the skill says so. It strongly reduces drift inside a job and improves reuse across a batch (oldest-first + TM write on Pass), but Hold jobs, separate runs, and legitimately different senses for the same English can still diverge.

How is the score calculated (high level)?

Start at 100; apply penalties for substantive edits and human flags; any hard-gate failure caps the score at 99 and blocks Pass. Typography-only fixes are not penalized. A numeric 100 alone is not enough if dispositions are not all Pass-equivalent.

What references does the agent use?
  • Company termbase (glossary)
  • Locale style guide and error-pattern checklist
  • Product translation memory (read-only during review)
  • i18n key path and namespace conventions
  • Job-local bilingual baseline and terminology audit artifacts

Termbase and style guide outrank TM when they conflict. The agent does not invent product facts or write TM directly outside the TMS confirmation path.

Why put decision points in terminology lookup?

Glossary writes are governance events. The skill stops for expand-search, create-or-skip, regional validation when needed, and final entry confirmation — so an LM stays in control while the agent does the research.

What is an FR term Note for?

To disambiguate sense for MT and LLM pipelines (and future reviewers) — especially when neighboring concepts share vocabulary but not meaning. Notes are part of making the termbase machine-usable, not only human-readable.
